Abstract

The rapid proliferation of generative artificial intelligence (GenAI) in higher education has fundamentally altered student problem-solving habits. Foundation large language models (LLMs) provide rapid knowledge synthesis; however, their standard configuration acts as unconstrained solution oracles. When learners encounter programming assignments or data science exercises, standard LLMs output turnkey scripts and complete derivations immediately. This precipitates acute cognitive offloading—the cognitive bypassing of essential mental struggles (germane cognitive load), precipitating competence collapse, superficial comprehension, and pervasive academic dishonesty.

To combat this crisis, this project introduces SocraticGuard, an adaptive pedagogical guardrail framework designed specifically for Computer Science and Data Science education. SocraticGuard replaces direct solution dispensation with a multi-tiered Socratic scaffolding loop (Tier 1: Conceptual Probe, Tier 2: Strategic Formulation, Tier 3: Diagnostic Clues). The system integrates a static AST and heuristic inspection engine that pinpoints syntax, memory, and semantic bugs across C/C++, Python, and Data Science workflows without revealing copy-paste solutions.

Empirical benchmarking against unconstrained baseline LLMs across 30 standardized academic STEM problems demonstrates that SocraticGuard completely eliminates premature answer leakage (reducing Answer Leakage Rate from 100.0% to 0.0%) while elevating the student's cognitive engagement from Level 2.0 (Recall/Understand) to Level 3.0+ (Apply/Analyze) on Bloom's Revised Taxonomy. Furthermore, unit testing encompassing 66 automated test cases demonstrates robust error identification across languages and zero degradation under multi-turn dialogue.

Keywords: Cognitive Offloading, Socratic Method, Intelligent Tutoring Systems (ITS), Generative AI, Bloom's Taxonomy, Academic Integrity, Static Code Analysis, Pedagogical Scaffolding.

Chapter 1: Introduction

1.1 Motivation & Context

The mainstream deployment of foundational language models has democratized personalized digital tutoring. Students across global universities routinely consult generative models to debug code, interpret mathematical theorems, and structure complex assignments. Despite these capabilities, prevailing generative models suffer from an inherent pedagogical misalignment: they are optimized for conversational efficiency and direct question answering.

In educational contexts, immediate answer generation short-circuits learning. Educational psychology, rooted in Sweller's Cognitive Load Theory, indicates that long-term retention and conceptual schema formation require deliberate intellectual struggle—specifically, germane cognitive load. When an AI generates full code for a binary search or automatically rectifies a data leakage error, the student acts as a passive consumer rather than an active problem solver.

1.2 Problem Statement

Standard commercial AI assistants cause three critical educational dysfunctions:

  • Competence Illusion: Students conflate the ability to prompt an AI with genuine mastery of algorithms and data structures.
  • Erosion of Foundational Debugging Skills: Novice programmers bypass learning compiler diagnostics, memory semantics, and boundary invariants because AI agents write the corrections automatically.
  • Academic Dishonesty & Plagiarism: Generative models facilitate homework and assignment evasion, rendering traditional static plagiarism detectors ineffective.

1.3 Project Objectives

The core engineering and research objectives of this project are:

  1. Develop an Anti-Cheating Diagnostic Guardrail: Detect and intercept student attempts to solicit complete code solutions.
  2. Implement Static & Semantic Code Analysis: Build language-aware inspectors for C, C++, Python, and Data Science pipelines that identify structural bugs (e.g. invalid return; in non-void functions, missing format specifiers, and data leakage) without disclosing solutions.
  3. Establish a Multi-Tiered Socratic Scaffolding Loop: Formulate dynamic pedagogical prompts across three distinct cognitive tiers to guide students incrementally.
  4. Create an Interactive Guided GUI: Deploy a two-panel side-by-side workspace separating student code editing from Socratic dialogue with real-time telemetry tracking.
  5. Empirically Benchmark Pedagogical Alignment: Measure quantitative metrics (Answer Leakage Rate, Bloom's Taxonomy Level) against unconstrained baselines.

Chapter 2: Literature Review & Theoretical Framework

2.1 Bloom's 2 Sigma Problem and Intelligent Tutoring

In 1984, educational psychologist Benjamin Bloom published seminal research demonstrating that students tutored one-to-one using mastery learning techniques performed two standard deviations (2 sigma) above peers in conventional classroom settings. Human tutors achieve this not by providing answers, but through continuous diagnostic questioning, tailored hints, and immediate feedback on student misconceptions—the classical Socratic method.

2.2 Cognitive Load Theory and Offloading

Cognitive Load Theory posits that human working memory is severely constrained. Learning requires transferring knowledge from working memory into long-term schema. When external digital tools automate task execution, extraneous cognitive load is eliminated, but germane load (schema construction) is inadvertently destroyed. In computing education, this phenomenon—cognitive offloading—leaves students unable to write or debug code independently.

2.3 Bloom's Revised Taxonomy in Computing

Cognitive engagement is formally categorized using Anderson and Krathwohl's Revised Bloom's Taxonomy:

Level Cognitive Category Computing Action Verbs Standard LLM Output SocraticGuard Output
1 Remember Recall, define, repeat Full direct solution / Code snippet Suppressed (Anti-Cheating)
2 Understand Explain, summarize, classify High-level descriptive summary Tier 1: Conceptual Probe
3 Apply Implement, calculate, execute Generated script to run Tier 2: Algorithmic Scaffolding
4 Analyze Diagnose, contrast, debug Automated error fix Tier 3: Diagnostic Clues
5 Evaluate Critique, defend, verify Rarely elicited Response Verification & Defense

Chapter 3: System Architecture & Implementation

3.1 System Pipeline Architecture

SocraticGuard is architected as an event-driven, decoupled pedagogical pipeline. The student interacts via a dual-panel Streamlit frontend that streams code updates and chat inquiries into the reasoning engine.

Architectural Invariant: At no stage does the pedagogical pipeline output a raw, copy-pasteable functional implementation block. All generated candidates pass through post-generation code sanitizers that replace solution blocks with guided pseudocode blanks.

3.2 Static Code Inspector Module (src/code_inspector.py)

The code inspection module provides stateful static analysis across multiple programming languages:

  • C and C++ Systems Diagnostics:
    • Function Scope & Return Analysis: Scopes function blocks, tracking function return types and statement depth. Pinpoints bare return; statements in non-void functions like int main(), while permitting them in void functions.
    • Input/Output Integrity: Flags beginner confusion such as print() versus printf(), missing <stdio.h> headers, and format specifier count/type mismatches.
    • Memory & Syntax Safety: Identifies missing terminating semicolons (ignoring trailing comments), unclosed braces/parentheses, uninitialized variables, and out-of-bounds literal array indexing.
  • Python Abstract Syntax Tree (AST) Engine:
    • Parses code into abstract syntax trees using Python's native ast module.
    • Detects SyntaxError and IndentationError with line numbers.
    • Identifies code anti-patterns: bare except: blocks, mutable default arguments, and unbounded recursive functions lacking base returns.
  • Data Science Pipeline Guard:
    • Data Leakage Detector: Flags calls to .fit() or .fit_transform() on test splits (X_test), verifying that test set statistics remain strictly unobserved during model training.
    • Pandas In-place Reassignment: Catches illegal assignments like df = df.dropna(inplace=True) which evaluate to None.

3.3 Socratic Scaffolding & Multi-Turn Memory (src/socratic_engine.py)

The scaffolding engine dynamically synthesizes prompts based on the learner's selected hint tier and maintains full multi-turn conversational history: 

# Example Tiered Prompt Synthesis
Tier 1 (Conceptual Probe):
"What assumption does your logic make regarding the array's boundary invariants?"

Tier 2 (Strategic Formulation):
"When the subarray narrows to low == high, what does your loop termination condition evaluate to?"

Tier 3 (Diagnostic Clue):
"Look at line 3: in C, 'print()' is not declared in <stdio.h>. What is the standard formatted output function?"

3.4 Student Response Verification Engine (src/mock_llm.py)

A pivotal capability of SocraticGuard is active verification. When a student answers a diagnostic question (e.g., *"1. It is C language 2. It takes no input"*), the system parses the response, affirms what was correctly identified, and advances the conceptual inquiry.

Chapter 4: Experimental Evaluation & Benchmark Results

4.1 Benchmark Methodology

To evaluate SocraticGuard quantitatively, we curated an empirical evaluation benchmark comprising 30 standardized academic problems spanning three core STEM domains:

  • Mathematics (10 questions): Single & multivariable calculus, linear algebra, probability, differential equations.
  • Computer Science (10 questions): Algorithmic complexity, binary search trees, graph theory, cryptography, memory addressing.
  • Physics (10 questions): Classical mechanics, electromagnetism, thermodynamics, quantum wavefunctions.

4.2 Evaluation Metrics

  1. Answer Leakage Rate (ALR): The percentage of initial-turn responses where the final solution string or full executable script was disclosed. Lower is superior (target: 0.0%).
  2. Cognitive Demand Level (CDL): Elicited cognitive demand scored on Bloom's Revised Taxonomy (1.0 = Recall, 6.0 = Create). Higher is superior.
  3. Pedagogical Alignment Index (PAI): A normalized composite index on a 1.0 to 5.0 scale balancing leakage suppression and cognitive demand.

5.2 Representative Case Studies

Case Study 1: Missing Return Value in C Function (int main())

When a student submits a C program with return; instead of return 0;: 

#include <stdio.h>
int main(){
    printf("hello world\n");
    return; // Bug: bare return in non-void function
}

SocraticGuard Diagnosis: Rather than fixing the line, SocraticGuard isolates line 4 and prompts: "Notice line 4: return;. In C, your main() function is declared with return type int. What value should main() return to the operating system upon successful completion?"

Case Study 2: Machine Learning Data Leakage

When a student fits a scaler on the test partition: 

scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train)
X_test_scaled  = scaler.fit_transform(X_test) # Data Leakage Bug

SocraticGuard Diagnosis: Flags the preprocessor call and inquires: "Notice how you are fitting your preprocessor on 'X_test'. Why is it critical that test data distribution parameters remain completely unobserved during model fitting?"
